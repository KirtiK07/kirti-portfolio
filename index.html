Sheet 1 of 6voice-triage-agent

Interruptible Voice Agent

A support-triage agent that stops talking the moment a caller cuts in, then answers what they just said.

Most voice demos talk over the caller or lose track of the turn. Here a voice activity detector listens during playback in 32 ms frames and cancels the in-flight LLM and speech stream, and transcription only starts after that. Cutoff and recovery are reported separately because they fail for different reasons.

Errata

  • A new reply takes over two seconds to start. The STT, LLM and TTS round trip is the bottleneck, and a caller will notice the gap.
  • Five scripted scenarios are enough to show the design works. They are too few to predict real tail latency.
Sheet 2 of 6llm-cost-router

Cost-Aware LLM Router

Sends each query to the cheapest model that can handle it, and answers near-duplicates from a semantic cache.

Teams often send every request to their most expensive model. This gateway checks the cache first, because a hit needs no model call. On a miss, a logistic regression over local embeddings picks the tier. Providers and cache backends sit behind interfaces, so adding a provider means adding one file.

Live demoSourceRaw results

Errata

  • The router's p95 latency (9,978 ms) is worse than always using the capable model (7,453 ms), because simple queries inherit the cheap tier's slow tail.
  • Cache hit rate in this benchmark is 0%. The eval set has no duplicates by design, so the cache's savings remain unmeasured.
  • 100% classifier accuracy is on a small hand-labeled set of 40. Real traffic will be messier.
Sheet 3 of 6rag-hallucination-guardrail

RAG Hallucination Guardrail

Checks every RAG answer against the text it was retrieved from and flags claims that text doesn't support.

Two verifiers are benchmarked against each other: an NLI cross-encoder that treats support as an entailment problem, and an embedding-similarity baseline that reuses the retriever's own model. Every eval entry runs real retrieval, so a retrieval miss can cause a false negative, as it would in production.

SourceRaw resultsDesign decisions

Errata

  • The NLI verifier catches almost everything but is noisy: 42% of what it flags is actually supported.
  • It verifies the whole answer at once, so it can't point to which claim is unsupported.
  • The corpus is small, drawn from the docs of two sibling projects, and the eval set has only 60 entries.
Sheet 4 of 6QueryPal

QueryPal

Upload a spreadsheet, ask a question in plain English, and get the SQL, a results table, a chart and a one-line takeaway.

Each account gets its own Postgres schema, so tenants can't see each other's data. If a query fails on a schema mismatch, the real database error goes back to the model for one automatic correction. A separate validator allows only reads, whatever the model was told to do.

Live demoSourceSafety tests

Errata

  • The validator scans with a regex, so it wrongly rejects WHERE status = 'update pending'. A test tracks this, and a real SQL parser would fix it.
  • The 16/16 covers safety only. End-to-end SQL accuracy and how often the retry rescues a query are not benchmarked yet.
Sheet 5 of 6CodeSense-AI

CodeSense AI

Code review with two independent opinions: a risk score learned from real defect history, and an LLM reviewer that reads the code.

A Random Forest trained on 10,885 NASA JM1 modules scores code from its complexity metrics. Gemini reviews the code separately and never sees that score. SMOTE is applied only to the training split, so the test set keeps its real class imbalance. Built as my MSc research project.

scikit-learnimbalanced-learnRadonLizardGeminiStreamlit

Live demoSourceModel performance

Errata

  • Recall on defective code is 0.38, so at the default threshold the model misses more than half of defective modules. The app uses risk bands instead of a hard cutoff, and tuning those bands for recall is the next fix.
  • Risk scores outside Python rest mostly on estimated features. The UI tells users this directly.
Sheet 6 of 6candor

Candor

Tailors a resume to a job description, works in only what the resume supports, and fact-checks every change.

Skills you don't have are listed as gaps and blocked if the model tries to add them. You get ATS-safe DOCX and PDF files, a diff of every change with reasons, and a fact-check report. If a provider runs out of credit or hits a rate limit, the run continues on the next one and tells you it switched.

StreamlitGeminiGroqOpenAISupabaseSQLite

Live app (sign-in required)Source

Errata

  • There's no published benchmark of how many invented claims the fact checks catch. The test suite runs offline against a fake LLM.
  • Scanned, image-only PDFs can't be parsed, so that text has to be pasted in.
  • The hosted app sits behind a login to protect API credit, so you can't try it without an account.
